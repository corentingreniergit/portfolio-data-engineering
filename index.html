Projet fil rouge · Formation Diginamic · équipe de 4 · en cours

Sherlock Homes - Refonte du SI d’une société de chasse immobilière

Reprise d’un système d’information existant pour une société fictive de chasse immobilière : audit de l’existant, refonte du modèle de données, industrialisation des flux de données et conception du parcours utilisateur futur intégrant l’IA.

  • MongoDB
  • MariaDB
  • MinIO
  • Airflow
  • Docker
  • Python
  • SQL
  • DuckDB

Architecture

Le projet part d’un extrait de base MySQL existant à auditer, puis à migrer vers un modèle de données corrigé. L’ensemble des traitements est conteneurisé avec Docker et orchestré par Airflow, selon une architecture en médaillon : MongoDB pour la couche Bronze (données brutes), MariaDB comme base métier OLTP et couche Silver (données nettoyées), MinIO pour la couche Gold (données agrégées avec DuckDB, consommées par Power BI) et pour le stockage des photos et vidéos. Le projet couvre :

  • Un audit de l’existant (schéma, anomalies, incohérences métier) formalisé en matrices de décision et journal de décisions 
  • Une refonte du modèle de données (MCD complet, cardinalités) et des scripts SQL de migration à partir des fixtures fournies 
  • Des pipelines Airflow orchestrant l’ingestion et le nettoyage de nuit, puis l’agrégation du matin vers la couche Gold 
  • Une API REST pour exposer les données du futur parcours utilisateur 
  • La conception d’un modèle de matching bien/demande en vue d’une intégration IA, avec une note dédiée à la souveraineté et à la sécurité des données exposées

Mon rôle : référent Data

  • Conception du schéma d’architecture présenté ci-dessous.
  • Validation de toutes les pull requests touchant à la donnée.
  • Création et configuration de l'environnement Docker.
  • En cours : script d’ingestion dans MongoDB, script d’agrégation et intégration de DuckDB.

Projet personnel · Data Engineering sur Azure + Databricks

Pipeline de données Spotify - Azure End-to-End

Pipeline d’ingestion et de transformation de données construit de bout en bout en suivant le projet d’Ansh Lamba sur YouTube, « Spotify End-To-End Azure Data Engineering Project », et adapté à mes besoins : j’ai corrigé les problèmes apparus avec les changements de version des services depuis la publication de la vidéo.

  • Azure Data Factory
  • Azure SQL Database
  • Azure Data Lake Storage
  • Azure Databricks
  • Azure Logic Apps

Architecture

Une base Azure SQL Database sert de source. Azure Data Factory orchestre l’ingestion vers un Data Lake avant transformation dans Databricks. On peut retrouver dans ce projet :

  • Un chargement incrémental table par table (paramètre loop_input, boucle ForEach) par watermark : une table de contrôle conserve la dernière valeur de la colonne CDC (last_cdc / max_cdc) pour ne charger que les données modifiées 
  • Une purge automatique des fichiers vides lorsqu’aucune donnée nouvelle n’est détectée (delete_empty_file) 
  • Un système d’alertes par e-mail (Azure Logic Apps + connecteur Outlook) déclenché en fin de pipeline pour suivre l’exécution
