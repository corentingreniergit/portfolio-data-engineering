Projet personnel · Data Engineering sur Azure + Databricks

Pipeline de données Spotify - Azure End-to-End

Pipeline d’ingestion et de transformation de données construit de bout en bout à partir du projet d’Ansh Lamba sur YouTube, « Spotify End-To-End Azure Data Engineering Project », puis prolongé avec un chargement incrémental piloté par CDC et un système d’alertes par mail.

  • Azure Data Factory
  • Azure SQL Database
  • Azure Data Lake Storage
  • Azure Databricks
  • Azure Logic Apps

Architecture

Une base Azure SQL Database sert de source. Azure Data Factory orchestre l’ingestion vers un Data Lake avant transformation dans Databricks. On peut retrouver dans ce projet :

  • Un chargement incrémental table par table (paramètre loop_input, boucle ForEach) piloté par une table de contrôle de type CDC (last_cdc / max_cdc), pour ne prendre en compte que les données modifiées 
  • Une purge automatique des fichiers vides lorsqu’aucune donnée nouvelle n’est détectée (delete_empty_file) 
  • Un système d’alertes par e-mail (Azure Logic Apps + connecteur Outlook) déclenché en fin de pipeline pour suivre l’exécution

Projet fil rouge · Formation Diginamic

Sherlock Homes - Refonte du SI d'une société de chasse immobilière

EN CONSTRUCTION

Reprise d'un système d'information existant pour une société fictive de chasse immobilière : audit de l'existant, refonte du modèle de données, industrialisation des flux de données et conception du parcours utilisateur futur intégrant l'IA.

  • Git
  • Docker
  • Airflow
  • Python
  • MinIO
  • MySQL
  • APIs REST

Architecture

Le projet part d'un extrait de base MySQL existant à auditer, puis à migrer vers un modèle de données corrigé. L'ensemble des traitements est conteneurisé avec Docker et orchestré via Airflow, avec MinIO comme couche de stockage objet Bronze et Gold pour les données brutes et les agrégations, et MariaDB comme base de donnée métier/couche Silver. On peut retrouver dans ce projet :

  • Un audit de l'existant (schéma, anomalies, incohérences métier) formalisé en matrices de décision et journal de décisions 
  • Une refonte du modèle de données (MCD complet, cardinalités) et des scripts SQL de migration à partir des fixtures fournies 
  • Des pipelines Airflow orchestrant l'ingestion et la transformation des données, avec MinIO en stockage objet 
  • Une API REST pour exposer les données du futur parcours utilisateur 
  • La conception d'un modèle de matching bien/demande en vue d'une intégration IA, avec une note dédiée à la souveraineté et à la sécurité des données exposées
